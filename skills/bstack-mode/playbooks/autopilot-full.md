### Autopilot-full

**You own the verdicts, never the PRs. One owner runs each PR from build to merge, and nothing merges without your clean verdict.** For a queue of independent PRs where the user granted landing authority in this conversation. Each PR's owner carries the whole lifecycle through the merge, and the root keeps only verification, countersigns, and audits. Coupled work, or a user who wants to review before landing, is `playbooks/autopilot-stack.md`. A multi-day program of stacked PRs whose coordinator lands work itself is `playbooks/orchestrate.md`. Every forge operation is `gh`.

1. **Mark the user's items and honor state-then-wait.** Items the user names stay with the user. The user reviews and clicks, and no owner merges one. When the user asks for the protocol or the plan to be stated, deliver the statement and stop. Execution starts only on the user's explicit go, and that go must include landing. Without it, run `playbooks/autopilot-stack.md` instead. On the go, write the full program objective at the top of the trail and re-read it at every audit tick.
2. **Spawn one owner per PR with the full lifecycle and an early trail.** Each owner is a `bstack-agent` on the code-delegate model (`references/models.md`) in `isolation: "worktree"`. It owns build, the first push, a ready PR, self-proof on the real artifact (`principles/prove-it-works.md`), review-comment triage on the merits (fix real findings, dismiss noise with a concrete reason), a read of its whole diff to cut comments that narrate what the code does, a rebase onto current trunk, the babysit loop to green (`playbooks/babysit.md`), and the merge itself. Within about 15 minutes, every owner starts a `decisions.tsv` trail per the `show-me-your-work` skill, pushes its first branch snapshot, and opens the PR ready, never draft. Open the PR before self-proof so the URL, decisions, and checks form a durable trail. Keep `decisions.tsv` uncommitted and return it with the report. The rebase always precedes babysit. The merge is the one step an owner may not take alone. Step 4 gates it.
3. **Run owners in true parallel and never stack.** Many owners at once when PRs are self-contained: one writer per branch, disjoint files, cross-PR drift absorbed by rebase. Only genuinely overlapping work serializes. Self-contained PRs branch off main, and sequenced work is merge-then-branch. The one exception is an owner that must split a dependent change, which may hold a short private base-branch stack.
4. **Verify every merge-ready head before its merge.** At the owner's merge-ready head SHA, spawn independent verifiers, one per lane, in one message, on a model other than the owner's, and aggregate to one verdict. The lanes: re-run the gates at that SHA. Prove the load-bearing behavior live on the real surface (the `run` skill). Audit the receipts and the diff, distrusting the PR body. Run the same scenario on current trunk as a regression lane. If trunk lacks the feature, record that and gate the behavior the diff adds plus the end state the user waits for. The live lane is the floor. A verdict without it is not clean. Findings go back to the owner for fix-forward, and the new head gets fresh verifiers and a fresh verdict.
5. **On a clean verdict the owner merges and takes the next item.** The owner merges only from a head freshly rebased onto trunk, and the verdict pins that SHA. If trunk moves before the merge, the patch-id rule in `playbooks/shipping.md` governs re-verification. The owner runs `gh pr merge <pr> --squash` and picks up its next self-contained item. The user's landing grant plus the root's clean verdict is the merge authorization that babysitting alone never has. User-named items stop at merge-ready and wait for the user's click.
6. **Run the root layer.** A genuinely new raise of a pinned gate or budget value (a limit CI only lets tighten) needs your fresh countersign, granted only after verifier proof. Absorbing values that already landed on main is drift, not a raise. Run an audit tick over all owners roughly every 30 minutes, armed with the `loop` skill, never left to memory or to completion notifications. At each tick, re-read `playbooks/autopilot-full.md` and the program objective, audit the operation against both, and fix drift in that tick. Probe each owner read-only (`gh`, pushed branches, `bstack-trace` on its transcript). Count only side effects as progress: commits, pushes, PR or check deltas, trail rows. A lane past its expected runtime with no side effect is stuck. Stand it down and dispatch a replacement at once. When merges batch, run a retro pass and a post-merge review-comment sweep.
7. **Stand down instantly on the user's stop.** Stop every running owner and log the hold in the trail. Nothing writes until the user releases it.

**Reply:** the queue with each PR's owner, state, and head SHA. Each verdict and the verifiers that produced it. What merged and what each owner took next. Countersigns granted and why. Open user gates. Where the collected decision trails live.
